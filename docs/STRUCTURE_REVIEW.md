# Agent Factory v0.1 구조 검토

검토일: 2026-09-19. 대상은 현재 로컬 저장소의 PowerShell 런타임, 템플릿,
프리셋, 상태·검증 계약과 사용 흐름이다. 특정 제품 앱의 품질을 평가한 것은 아니다.

현재 폴더 구분과 실행 책임은 로컬 v0.1에 적절하다. 다만 검토 범위와 승인 근거가
어긋나는 문제가 있어 현재 상태를 최선 또는 검증 완료된 구조라고 판정할 수 없다.
전체 재설계보다 아래 정확성 문제를 먼저 수정하고, 실제 작은 앱 한 개로 사용 흐름을
검증하는 순서가 적절하다. 이번 요청에서는 검토와 사용 문서만 작성했으며,
아래 런타임 문제는 수정하지 않았다.

## 유지할 구조

| 현재 구분 | 유지할 이유 | 근거 |
| --- | --- | --- |
| `template/` / `presets/` / `scripts/` | 공통 개발 규칙, 기술별 앱 골격, 실행기를 각각 바꿀 수 있다. | `scripts/new-app.ps1`, `docs/ARCHITECTURE.md` |
| PowerShell의 상태 관리 / Codex의 작업 수행 | 모델의 완료 주장 대신 실제 명령 결과와 검토 결과로 작업 상태를 결정한다. | `scripts/workflow.ps1:72`, `scripts/common.ps1:223` |
| 한 번에 한 작업, 최대 3회 시도 | 실패한 작업을 건너뛰지 않고 어느 작업을 재개할지 추적할 수 있다. | `scripts/workflow.ps1:72`, `scripts/agent.ps1:44` |
| 프로젝트 잠금과 상태 전환 기록 | 중복 실행을 막고 ROADMAP/STATUS 저장 중단 후 복구할 수 있다. | `scripts/common.ps1:215`, `scripts/state.ps1:3` |
| 앱에 런타임 복사 | 생성 앱이 원본 Factory의 절대 경로에 의존하지 않는다. | `scripts/new-app.ps1`, `docs/DECISIONS.md` ADR-006 |
| PR·릴리스 준비와 외부 실행 분리 | 로컬 검증에서 push·배포로 자동 진행하지 않는 경계가 명확하다. | `scripts/workflow.ps1:242`, `scripts/workflow.ps1:262` |

이는 현재 코드에 대한 주 에이전트의 설계 판단이다. 모든 규모·팀·제품에 대한
최적성을 입증한 결과가 아니며, 독립 설계 검토의 승인도 아니다.

## 수정이 필요한 발견

### 1. 높음 — 리뷰 갱신의 요청 범위와 역할 지시가 충돌

- 근거: `scripts/workflow.ps1:195`는 수동 변경을 포함한 전체 diff를 검토하라고 요청한다.
  반면 `scripts/codex.ps1:16`, `:26`이 주입하는 developer instructions의
  `template/automation/prompts/tester.md:8`, `reviewer.md:8`, `security.md:8`은
  정확히 선택한 작업만 검토하라고 제한한다.
- 영향: 마지막 완료 작업 밖의 수동 변경이 검토에서 제외돼도 현재 전체 소스의
  fingerprint에 통과 근거가 연결될 수 있다. 이후 PR·릴리스 준비가 이 근거를 사용한다.
- 확신: 지시 충돌은 정적 코드로 확인했다. 실제 모델이 다른 변경을 누락하고 통과시키는
  전체 실행은 재현하지 않았으므로 그 결과는 가능한 실패 경로로 구분한다.
- 개선: 작업 검토와 전체 변경 갱신 검토의 계약을 구분하고, 검토 기준점·대상 변경·범위를
  결과에 기록한다. 세 역할 모두 같은 전체 변경 계약을 받아야 한다.
- 검증 조건: 마지막 작업과 무관한 수동 변경을 넣었을 때, 마지막 작업만 다룬 검토 결과로는
  전체 근거가 갱신되지 않는 회귀 테스트가 필요하다. 실제 모델 파일럿도 별도로 수행한다.

수정 전에는 `ai-review`의 통과를 앱 전체 또는 다른 작업의 변경까지 검토했다는
증거로 사용하지 않는다. 전체 변경에 대한 별도 검토가 필요하며, 이 운영상 주의는
코드 결함의 수정이나 독립 검토 범위 보증을 대신하지 않는다.

### 2. 중간 — ROADMAP의 프로젝트 식별 검증 누락

- 근거: `docs/ARCHITECTURE.md:21`에는 `project:string`이 필수지만
  `scripts/common.ps1:29`의 `Assert-AfRoadmap`은 해당 필드를 검사하지 않는다.
  `scripts/agent.ps1:27`의 시작 경로에도 config와 ROADMAP의 프로젝트 이름 비교가 없다.
  `scripts/state.ps1:9`의 복구 역시 같은 검증기를 사용한다.
- 재현: 독립 코드 리뷰의 직접 호출 검사에서 project 누락 및 다른 이름이 있는
  ROADMAP 모두 검증을 통과했다. 확신은 높음이다.
- 영향: 다른 앱에서 복사한 계획이나 잘못된 상태 파일을 초기에 식별하지 못한다.
  초기화 시 모델 출력의 이름을 확인하는 경로만으로 이후 로딩·복구를 보장할 수 없다.
- 개선: 비어 있지 않은 문자열을 요구하고 로딩·복구 시 `agent-factory.json.project`와
  대소문자를 구분하여 일치 여부를 확인한다.
- 검증 조건: 누락·빈 문자열·타입 오류·다른 프로젝트·복구 기록의 불일치를 거절하고,
  정상 프로젝트는 계속 처리하는 테스트가 필요하다.

### 3. 낮음 — 초기화 오류 문구가 제거할 줄을 모호하게 안내

- 근거: `scripts/workflow.ps1:43`은 `State: UNINITIALIZED`가 남아 있으면 거절하지만,
  오류의 “including its State: UNINITIALIZED line”은 그 줄을 포함하라는 뜻으로 읽힐 수 있다.
- 개선: 실제 IDEA 작성 후 해당 줄을 제거하라고 명확히 안내한다.
- 상태: 런타임 문구는 아직 그대로다. 새 사용 예시에는 제거해야 한다고 명시했다.

독립 코드 리뷰 결과는 **REQUEST CHANGES(수정 필요)**다.
높음 항목을 수정하기 전에는 갱신 리뷰 근거가 모든 변경을 포괄한다고 승인할 수 없다.

## 사용 편의성과 유지보수 판단

아래는 현재 코드에서 추론한 개선 제안이며, 재현된 실행 결함과 구분한다.

| 순서 | 제안 | 현재 근거와 적용 시점 |
| --- | --- | --- |
| 1 | 앱 진입과 상태 안내를 간단히 만들기 | `scripts/profile.ps1:3`은 세션 전역 런타임 경로를 사용한다. 새 터미널·다른 앱으로 이동할 때 앱 profile을 다시 등록해야 한다. 현재 TXT에 정확한 순서를 제공했으며, 후속으로 앱별 진입 명령과 “다음 할 일” 출력을 고려한다. |
| 2 | 프롬프트의 기준 원본을 하나로 관리 | `template/.codex/agents/*.toml`과 `template/automation/prompts/*.md`에 역할 지시가 중복된다. 런타임은 Markdown을 읽는다. 한 원본에서 두 형식을 생성하거나 일치 검사를 두면 서로 다른 동작으로 변하는 위험을 줄일 수 있다. |
| 3 | 기존 앱 런타임 업데이트 절차 마련 | 앱마다 런타임을 복사하고 버전을 기록하지만 업데이트·마이그레이션 명령은 없다. Factory를 고쳐도 기존 앱에 자동 반영되지 않는다. 여러 앱을 운영하기 전에 버전 비교·변경 미리보기·백업·회귀 검증 절차가 필요하다. |
| 4 | 스택 확장보다 실제 사용 파일럿 먼저 | 두 웹 시드는 검사했지만 실제 모델 전체 사이클은 미검증이다. 작은 로컬 앱으로 계획→한 작업→검토→실패 재개를 검증한 뒤 Toss·Unity·네이티브로 확장하는 편이 현재 불확실성을 직접 줄인다. |

현재 규모에서는 상태 저장소를 데이터베이스로 교체하거나 별도 서버·복잡한 플러그인
프레임워크를 추가할 근거가 부족하다. 현재 경계를 유지하며 정확성과 사용 절차를
개선하는 것을 권고한다. 새 패키지나 런타임 구조 변경은 이번에 추가하지 않았다.

## 검토와 검증 범위

- 독립 코드 리뷰: 12개 파일을 검토하고 위 3개 항목을 보고했다. 대상 PowerShell
  스크립트 8개의 AST 구문 검사가 통과했다. 검사 범위에서 하드코딩한 비밀값이나
  명령 문자열 평가·인자 연결로 인한 주입 패턴은 발견되지 않았다.
- 독립 설계 리뷰: 지정된 architect 모델 `gpt-5.4-mini`가 현재 ChatGPT 계정에서
  지원되지 않아 실행하지 못했다. 다른 검토자의 승인으로 대신 표시하지 않는다.
- 최신 구축 검증: 자가 테스트 **49 passed, 0 failed** 및 두 프리셋의 실제 웹 품질
  검사 통과. 상세 근거는 [검증 기록](VERIFICATION.md)에 있다. 이 결과는 위 후속
  발견을 해결하거나 실제 모델 동작을 입증한 것이 아니다.
- 사용 예시: PowerShell 예시 26개를 AST로 검사했다. 별도 임시 앱에서 실제 생성,
  앱 profile 등록, status와 init/next/run의 DryRun을 확인했다. 이 확인에서는 모델을
  호출하거나 제품을 구현하지 않았다.
- PSScriptAnalyzer, 실제 Codex 전체 사이클, 브라우저 E2E, 네이티브 빌드와 원격 CI는
  이번 검토에서 실행하지 않았다. 문서 변경만 수행하여 전체 회귀 테스트를 재실행하지 않았다.

사용자가 복사할 명령과 다음 날 재개·오류 복구 예시는
[Agent_Factory_사용_예시.txt](../Agent_Factory_사용_예시.txt)에 저장했다.
